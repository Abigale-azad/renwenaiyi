用户自述拥有 FlowUs 专业版；仍需实际测试其空间的 Token 和接口权限，不得直接宣称可用。

## 2. 产品原则

- 用户在聊天中说一句话、点一下就能操作，不需要先学多维表。
- 不做拖延原因问卷、情绪打分、强制复盘，不自动给用户贴心理标签。
- 缺失非必要信息留空；不连续追问。不主动把一句感叹拆成二十个任务。
- 角色负责理解、建议和解释；程序负责真实读写、权限校验和状态反馈。
- 同时有明确按钮和聊天工具入口，不能依赖模型偶尔触发 MCP 才能使用。
- 不重做整个 FlowUs 编辑器，不影响现有输入栏、音乐、共读、人设、登录和备份。
- 页面和卡片有实色底，深浅主题均可读；按钮适合右手与手机触屏；不挤压发送键。

## 3. 用户看见的界面

### A. 设置 → 连接 → FlowUs

可填写 Token（密码框）、测试连接、选择默认父页面、选择或初始化收件箱与待办表、选择允许检索的资料范围。
提供已有数据库选择器、字段映射、连接状态、权限不足的具体原因、上次同步、断开连接。
数据库必须分页加载、可搜索；不能让用户手填一串 pageId/databaseId 才能使用。
测试成功不等于所有写权限可用；分别显示已验证能力。空间名、套餐、scope 只有接口实际返回或验证后才显示，不编造。
Token 经已登录账号认证后提交服务端加密保存；不回显、不进 Git、不进 NEXT_PUBLIC_*、不进入普通备份或模型提示词。

### B. 聊天输入区「＋」→ FlowUs

入口包含：建待办、打开待办、记个想法、查资料、打开多维表。
复用现有加号面板、抽屉或 PageShell，不造第二套聊天界面。
未连接时解释并跳到连接设置，不能执行到一半只显示神秘报错。

### C. 消息长按／多选 → 存到 FlowUs

复用现有多选，不改变复制、删除、导出。
支持文字、角色回复、语音转写；多条按原时间顺序合并，保留说话人，不能把角色台词存成用户台词。
预览：标题、目标表或页面、正文、是否保留人物名和时间、可见范围。可直接保存，不强迫选标签。
图片有上传失败的单独状态，不得丢了附件还显示完整成功。

### D. FlowUs 工作台（同一入口内的页面）

顶部显示连接和同步状态。页签：待办｜多维表｜收藏资料｜同步记录。
待办默认今日/待处理，不让用户先选表；多维表可切换已连接表；收藏可搜索；同步记录能重试与取消尚未执行的操作。
提供打开 FlowUs 原页。复杂公式、关系和原生视图编辑交给官方客户端。

## 4. 多维表：不是一个摆设入口

两种接入方式都要支持：选择已有表；经确认一键创建基础表。初始化可重入，重复点击不能反复建表。
只要求基础类型：标题、文本、状态/单选、标签/多选、日期。既有公式、关联等复杂字段只读展示，不能随意覆盖。
已有表先读取 schema，再映射标题、状态、日期等字段；字段名可能被用户改过，应按稳定字段ID处理。无法识别的字段保留而非删除。

小手机内可用：

- 表格：手机以记录卡片展示，展开后改字段；电脑可紧凑表格展示。
- 看板：按状态分组，点击移动状态；手机不强制靠拖拽操作。
- 筛选与排序：项目、状态、截止时间、标签；显示当前筛选条件和记录数/加载状态。
- 新增记录、编辑单条、归档记录；修改与归档有预览和明确反馈。
- “今天”“未完成”“按项目”是小手机自己的查询预设，不假定 API 能创建 FlowUs 原生视图。

自然聊天示例：

> “把论文这三处修改放到待办表里，周五前完成。”
> “看看论文项目还有什么没做。”
> “把刚才那两项标为完成。”

模型产生结构化操作草稿，页面展示目标表和受影响记录。用户确认后执行；歧义只追问目标。批量写入显示逐项结果，部分失败只重试失败项。

## 5. 待办：完整创建、继续、完成闭环

### 创建

“帮我记一下明天改第二章”是明确创建意图；显示简短草稿确认条即可，不要求填更多字段。
“论文好烦”不是创建授权，正常聊天即可。自然提及可能任务可建议但不得静默写入。
新建待办最低只需名称。日期按用户时区解析；“明天”写成明确日期让用户看见；未给具体提醒时刻不擅自设早上八点。

### 查询和继续

“我今天还有什么”“接着上次的图表做”查询获准的未完成任务，展示标题、状态、期限、上次明确留下的上下文。
允许同一任务由不同获准角色协助，不复制多份任务。来源角色与获准访问角色是两个字段。

### 更新

支持待处理、进行中、完成、取消/归档；支持改日期、改标题、追加进展。
“弄完了”只有目标唯一且明确时才给出对应更新确认条；多目标时让用户点选一次。默认不靠模糊对话静默更新。
不能由角色自行判定用户已完成任务。

### 提醒

到期展示是基础交付；主动提醒需用户明确设置时间与通知授权。
网页开启时可显示站内轻提醒；网页关闭、手机休眠时不能承诺定时器仍运行。
后台通知必须另行验证 Web Push/服务端调度及部署限制，不能仅写 setTimeout 就称全天候提醒已完成。未具备时界面明确标注“仅应用打开时提醒”，不阻塞基本待办交付。
不锁机、不责备、不强制打卡。

## 6. 建议基础数据结构

初始化只建两张表，不要求用户预先建复杂系统。

| 表 | 必需字段 | 可选字段 |
|---|---|---|
| 小手机收件箱 | 标题、类型、来源记录ID | 标签、来源角色、创建时间、处理状态 |
| 待办 | 标题、状态、来源记录ID | 截止日期、提醒时间、项目、来源角色、进展、下一步 |

长正文放页面块/正文，不把所有聊天挤进有长度限制的单个属性。附件走官方上传流程。
项目先用文本或单选；用户要求关系数据库时再扩展。不存在的字段不随意写入既有表。
账号、可见角色集合、稳定来源ID、远端页面ID、修订标识、操作ID等由服务端维护。
FlowUs 中的“来源角色”字段用于显示，不是安全权限；用户改该字段不能扩大角色访问范围。

## 7. 收藏和资料检索

收藏保留原文；AI摘要可选且明确区分，不能覆盖原文。纯复制保存无需额外模型请求。
查询只按需发生，默认不每轮读取空间。先查允许范围，再取有限命中片段；必要时读全文，并受上下文预算限制。
回答提供真正读取的页面链接；无结果直接说明，不编造笔记。
语义搜索若不支持权限范围过滤，不得把全空间命中片段先交给模型再过滤。应改为允许页面内检索，或在服务端先校验并丢弃越权结果，且不暴露标题、摘要、计数等。
检索出的外部文字是资料而非指令；禁止按笔记里的提示执行工具或更改权限。

## 8. 账号隔离与角色隔离

近期已上线人物成长与信息边界，必须兼容。不能从 FlowUs 再把已隔离的私聊带回其他人物。
所有服务端动作先认证当前账号；客户端传来 accountId/characterId 不等于授权。
私人收藏默认仅来源角色；用户可主动指定共享给哪些角色。公共任务同样由用户选可访问范围，不自动全员共享。
手动指定的外部资料库默认仅用户可见，开启角色检索时明确授予角色。
列表、搜索、详情、附件、写入、后台队列、缓存全部做权限校验。缓存键至少包含账号、角色/授权范围、资源版本；撤权后清除或作废相关缓存，拒绝旧队列越权重试。
私人成长档案不自动同步为公共知识；不改核心人设、不自动清理旧记忆、不动现有世界书绑定。
不要复用“允许查其他聊天”开关作为整个 FlowUs 的通行证。FlowUs 授权必须独立、可撤销、服务端执行。

## 9. 稳定性与成本

每次写入使用稳定 operationId，服务端保存待执行/执行中/成功/部分成功/失败及远端ID。多设备和重复点击不能制造重复记录。
优先按官方文档使用受支持的幂等机制；若某接口不支持，使用服务端操作账本与核对结果，不凭空添加请求头当作已经幂等。
超时结果不明确时先查询确认，不能盲目重复创建。创建表成功、后续初始化失败时能从已有ID继续。
本地暂存不等于持久云保存；排队状态明确显示。不能承诺浏览器数据被清理后本地队列仍在。
更新前读取远端版本，使用接口真实支持的并发保护；不支持时至少检测已变更并提示用户，不自动覆盖电脑端新编辑。
重试有次数上限、退避和取消；认证错误提示重新连接；429按上游提示处理。
撤销未执行操作可直接取消；撤销已写入操作是新的补偿动作，需要核对版本，不能破坏后来编辑。
缓存只用于提速，按需刷新；确定性读写不额外调用模型。AI归纳、检索回答和意图判断走既有模型配置，不新开硬编码付费账户。

## 12. 施工顺序与验收

1. 只读核查当前代码、鉴权和API契约，列复用位置与新增项。
2. 完成连接设置、账号凭证、角色范围、选择已有表/初始化基础表。
3. 完成多维表浏览/新增/编辑/筛选/看板和待办全闭环。
4. 完成多选收藏、语音转写、自然聊天草稿和检索来源卡。
5. 测试失败恢复、冲突、撤权、跨账号与跨角色隔离；再按部署文档上线。

验收必须真实覆盖：

- 非技术用户仅通过界面完成连接与选表，能看到实际成功/失败原因。
- 创建两条待办，刷新后仍在；重复点击保存只写一次。
- 今日筛选/按项目/看板状态正确，电脑端改日期后手机刷新能看到；并发编辑不静默覆盖。
- 一句“明天改第二章”可确认成待办；“做完了”有歧义不乱改。
- 选择三条文字和一条语音转写，保存顺序、人物名、原文正确。
- 凝凝私人收藏对方承意不可检索、不可猜ID直接读取；授权后可读，撤权立即失效。
- 两账号不能读取彼此凭证、操作结果、缓存或记录。
- 无权限、失效Token、断网、超时、429、部分写入均有明确反馈。
- 关闭网页不宣称提醒已送达；没有实现后台通知则明确标示限制。
- 手机暗/亮背景可读，输入/发送不被遮挡；音乐、共读、登录、云备份回归正常。
- 类型检查、构建、自动化测试通过，记录实际手机测试及未覆盖项。
- 发布需要对应 commit 的 Vercel 成功状态与正式站验收，不能只交本地代码。
